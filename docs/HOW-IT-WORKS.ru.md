## 1. Общая схема

```
 Start-Windows.bat / Start-Mac.command / start.sh
        │  находит или скачивает Python, один раз проверяет данные
        ▼
 launcher.py ──► server.py  (http://127.0.0.1:8765, только этот компьютер)
                   │  отдаёт web/  ─────────────►  браузер: весь интерфейс (web/js/*.js)
                   │  /api/youtube, /api/link        граф нод, авто-поиск, OCR, SGA, звук,
                   │  /api/vigenere, /api/diagnostics  файлы, досье, клавиатуры
                   ▼
                 backend.py ──► vigenere/  (Python-движок: numpy на ядрах CPU, torch на CUDA)
                                   └── data/  (словари, корпуса, кэш языковых моделей)
```

* **Интерфейс — обычный JavaScript** без сборки. Каждый модуль — самовызывающаяся функция, которая регистрирует себя в общем объекте (`G.CipherOps`, `G.NodeTypes`, `G.Solver`…). Поэтому `web/index.html` открывается и прямо с диска (`file://`); тогда выключено только то, чему нужен сервер: Python-движок Виженера, проверка YouTube и ссылок, OCR через tesseract.
* **Сервер** написан только на стандартной библиотеке Python (`http.server`). Он слушает 127.0.0.1, отдаёт `web/` и несколько JSON-адресов.
* **Тяжёлый движок Виженера** лежит в `vigenere/` и работает внутри процесса сервера как задачи (`backend.py`): numpy на всех ядрах CPU через `multiprocessing` и, если есть, torch на видеокарте NVIDIA.
* **Данные** (списки слов, корпуса текстов, кэш языковых моделей; около 300 МБ в распакованном виде) в репозиторий не входят. Они скачиваются один раз архивом из релиза и проверяются по SHA-256.

## 2. Запуск и установка в один клик

Пользователь дважды щёлкает один файл. Дальше (`Start-Windows.bat`, `launcher.py`, `setup_data.py`, `tools/bootstrap-python.ps1`):

1. **Поиск Python.** Скрипт запуска пробует по очереди: собственную копию `runtime/python`, затем `py -3`, `python`, `python3`. Каждый кандидат проверяет `tools/pycheck.py` (Python ≥ 3.9 и 64 бита). Если на Windows подходящего Python нет, `bootstrap-python.ps1` скачивает с python.org официальный *встраиваемый* Python 3.12 в `runtime/python` (около 10 МБ), включает `site` в его файле `._pth`, ставит pip через `get-pip.py` и проверяет запуск. В систему ничего не устанавливается.
2. **Быстрый путь.** Если есть `runtime/setup-done.json`, его версия совпадает и быстрая проверка находит файлы данных, лаунчер сразу запускает сервер (около 3 с).
3. **Первый запуск.** Иначе лаунчер:
   * ставит `numpy` (а `torch` — только с `--gpu`) в собственный Python или в `.venv`;
   * запускает `setup_data.py`: читает `data.manifest.json` (имена файлов, размеры, SHA-256), скачивает `arg-decoder-data-v1.zip` по адресу из `config/release.json` с докачкой (файл `.part` и HTTP `Range`), прогрессом и четырьмя повторами, проверяет хеш архива, распаковывает только плоские записи `data/<имя>` (всё с `..` или подпапками пропускается) и сверяет каждый файл с манифестом. Если релиз недоступен, данные собираются из исходных публичных источников (`vigenere/download_data.py`);
   * делает самопроверку: движок должен расшифровать `LMVCCIKB` ключом `LUCY` в `ASTEROID`;
   * записывает `runtime/setup-done.json` и запускает сервер.
4. **Флаги.** `--repair` — всё заново, `--offline` — без сети, `--gpu` — добавить PyTorch с CUDA, `--check` — только проверить. Обновления: `--update`, `--check-update`, `--verify` (файлы программы против подписанного списка сборки) и `--rollback` (см. README, «Обновления»).
5. **Прогрев.** При старте сервера `backend.py` в фоне загружает языковые модели (из кэша `.npz`, примерно 1–1,5 с на модель), считает хеши словарей и проверяет CUDA. Всё это видно на вкладке **Отладка**.

В имени файла кэша модели есть *подпись содержимого*: SHA-256 первого и последнего мегабайта каждого исходного файла плюс его размер (`vigenere/core.py: data_signature`). Изменился словарь — модель пересоберётся; папку перенесли на другой компьютер — кэш остаётся годным.

## 3. Граф нод

**Модель** (`web/js/graph.js`). Граф — это ноды `{id, type, x, y, params}` и связи `{from, to, port}`. Тип ноды — либо *операция* из `G.CipherOps` (чистая функция: строки на входе, строка на выходе), либо *специальная нода* из `G.NodeTypes` (со своим интерфейсом: ввод, результат, авто-поиск, картинка, звук, файл…).

**Вычисление** — обход в глубину с запоминанием:

* сначала вычисляются входы ноды; если нода встретилась на текущем пути второй раз, это цикл и ошибка «цикл в графе»;
* если на входе ошибка, нода не запускается, а получает `inputError` со ссылкой на первую сломанную ноду выше по цепочке. Холст обводит эту ноду красным как *виновника*, поэтому длинная сломанная цепочка показывает на настоящую причину;
* параметры операции берутся из её полей, но если у операции есть второй вход (ключ, второй текст) и к нему подключён провод, значение берётся с провода;
* результаты хранятся по нодам (`graph.results`) и показываются в панели вывода ноды: длина, HEX, копирование, найденные ссылки.

Холст пересчитывает граф через 120 мс после правки (`requestEval`) или раз в кадр, пока тянут ползунок (`requestEvalFrame`), поэтому ползунки картинок дают живой предпросмотр. После каждого пересчёта холст отправляет событие `graph-evaluated`; гид примера по нему обновляет список шагов, в том числе когда долгий OCR закончил работу.

**Загрузка файла недоверчивая.** Параметры проверяются по схеме своего типа, неизвестные типы и неверные порты отбрасываются, связи, которые замкнули бы цикл, пропускаются, и всё это перечисляется в `graph.loadReport`, а не теряется молча.

**Артефакты** (`web/js/artifacts.js`). Файлы (картинки, звук, видео, архивы, логи) хранятся в проекте один раз как data URL и передаются по проводам ручками `artifact:<id>`. Обработка картинок и звука создаёт *производные* артефакты: они живут только в памяти и кэшируются по рецепту (`imgproc.recipeKey`), так что одна и та же цепочка правок не считается дважды.

**Отмена и раскладка.** Каждое изменение — снимок в стеке отмены (Ctrl+Z / Ctrl+Y). *Упорядочить* раскладывает ноды по колонкам по глубине потока данных; *Показать всё* вписывает ноды и рисунки в экран и оставляет место под гид примера, если он открыт.

## 4. Оценка текста: «похоже ли это на ответ?»

`web/js/scorer.js` ставит каждой строке оценку. Это мера того, насколько строка похожа на обычный текст или на годную ссылку, а не вероятность того, что это решение.

**Язык.** Для английского и русского (украинский текст в браузере оценивается русской моделью) считаются две вещи:

* **Квадграммы.** Логарифмы вероятностей всех четвёрок букв (таблицы в `web/js/lang-data.js`, квантованы в 8 бит). Среднее нормируется так, что случайные буквы дают ≈ 0, а обычный текст ≈ 1.
* **Покрытие словами.** Динамическое программирование по каждой группе букв находит разбиение на словарные слова, покрывающее больше всего букв (слова от 5 букв весят 1, из 4 — 0,85, из 3 — 0,55, служебные из 1–2 букв — 0,35). Результат — доля покрытых букв и список найденных слов.

Они смешиваются с весом, зависящим от длины: квадграммы дают 55 % при 20+ буквах, 45 % при 12+, 30 % при 7+, 20 % на более коротких, и ещё примерно вдвое меньше, если букв меньше 15 и слов не нашлось. Короткую строку слишком легко «подделать» одними квадграммами.

**Проверки сверху:**

* если одна буква занимает больше ~15 % длинного текста (для коротких фраз порог выше), языковая оценка делится пополам: это след повторяющегося шифра, а не язык;
* смесь латиницы и кириллицы снижает оценку; строкам короче 4–5 букв доверия меньше;
* непечатаемые байты стоят 140 очков за единицу доли;
* ссылка даёт минимум 60 очков, +30 за известный сервис (YouTube, Drive, Catbox, Pastebin…); ссылка ещё в виде `%HH` теряет 20, потому что полная расшифровка ценнее;
* строка вида 11-символьного YouTube ID или ID Google Drive помечается как ID; случайные «слова» внутри ID ничего не значат, поэтому язык для неё почти не учитывается;
* строка, похожая на ещё один слой кодировки (`%HH`, hex, двоичный код, цифры, Морзе, Base64), помечается `слой:` и получает высокий *потенциал*: это не ответ, но её стоит декодировать дальше.

Строка **читаема**, если языковая оценка не ниже 0,5, букв не меньше трёх, найдены слова и мусора меньше 5 %.

## 5. Авто-поиск

`web/js/solver.js` выполняет **лучевой поиск по цепочкам операций**.

**Корни.** Поиск начинается с самой строки и, если она длинная, ещё с 12 кандидатов, вырезанных из неё (hex, Base64, двоичные группы, ряды чисел, которые находит `candidates.js`; см. [раздел 7](#7-ссылки-id-и-кандидаты-в-длинном-тексте)). Если строка уже читается как текст, ссылка или ID, она добавляется как результат *как есть* с небольшим бонусом. Если в строке не меньше 30 букв и она не похожа на слой кодировки, взлом Виженера без ключа сразу добавляет три лучших варианта.

**Расширение.** Для каждого состояния луча и каждой операции, у которой есть функция `probes`, операция предлагает наборы параметров именно под этот текст (Цезарь — сдвиги, Виженер — ключи из банка ключей проекта и активного профиля, `dec_codes` — ширину групп и сдвиг и т. д.). Каждый выход оценивается и сохраняется, если он новый или объясняет тот же текст проще. Правила отсекают бессмыслицу ещё до вычисления:

* операция никогда не повторяется сразу и не идёт после своей обратной (hex-кодирование → hex-декодирование);
* буквенные шифры не пробуются на hex, цифрах, двоичном коде, Base64, `%HH` и Морзе, а также на строках, где букв мало;
* две подстановки подряд пропускаются (Цезарь после Виженера почти никогда не помогает, а шума даёт много);
* уже читаемую строку дальше не шифруют;
* байты не из ASCII после декодера в том же шаге читаются как UTF-8 и CP1251.

**Ранжирование** (`chainRank`). Ранг результата — оценка текста плюс:

* средний *приор* использованных операций (насколько часто каждая встречается в настоящих загадках);
* +30 за *чистое декодирование*: снят слой (числа, `%HH`, hex, Base64) без подстановок, и получились буквы одного алфавита;
* +25 за кандидата, вырезанного из лога и расшифрованного до читаемого слова;
* бонус за ключи, которые пользователь внёс в проект, и за любимые параметры активного профиля (например, `+23` у профиля mslan);
* минус 5 очков за единицу *цены объяснения* (сумма цен шагов; экзотика вроде аффинного, «изгороди», Плейфера стоит 2);
* минус 25 (или 50) очков за **неоправданный шаг-шифрование**: преобразование, которое подняло читаемость меньше чем на 0,12 по сравнению с родителем;
* минус 2 очка за бит **свободы параметров**: операция, перебравшая N вариантов, платит 2·log₂N, потому что чем больше попыток, тем легче случайно попасть в слово.

**Луч.** После каждого уровня в следующий луч идут 150–160 состояний с наибольшим потенциалом, но не больше четверти луча от одной операции, чтобы 25 сдвигов Цезаря не вытеснили всё остальное. Глубина — 1–4 уровня (режимы *Быстро*, *Обычно*, *Глубоко*).

**Уверенность.** Результат считается убедительным, только если это ссылка, чистое декодирование, текст *как есть* или читаемый текст, для которого не пришлось угадывать параметры шифра (или пришлось, но в нём не меньше 8 букв либо использован ключ проекта). Если убедительного нет, панель так и пишет, а не выдаёт шум за ответ.

**Отзывчивость.** Поиск идёт в основном потоке страницы кусками по 25 мс с паузами между ними, поэтому окно не зависает и Web Worker не нужен (из `file://` он не запускается). Поиск останавливается по лимиту времени (по умолчанию 25 с) или по кнопке. В итоговом списке до 300 результатов плюс лучший результат для каждого ключа проекта, чтобы введённый пользователем ключ не потерялся в шуме.

**Профили и банк ключей** (`web/js/profile.js`). По умолчанию профиль *neutral*: без чьих-либо ключей и привычек. Профиль (например, *mslan*) может добавить ключевые слова, любимые параметры и привычки (операции, которые автор любит, — их тогда не штрафуют как неоправданные). В банке ключей лежат ключи, найденные или введённые в этом проекте, вместе с происхождением; решатель пробует их первыми.

## 6. Виженер: три решателя

### 6.1 Взлом без ключа в браузере (`vigenere-crack.js`)

Работает внутри авто-поиска. Для каждой длины ключа до 8–10 (но не больше половины числа букв) текст делится на столбцы, сдвиг каждого столбца подбирается по частотам букв, затем ключ уточняется побуквенно по квадграммной оценке. На коротких строках (меньше ~5 букв на позицию ключа) это только догадка.

### 6.2 Встроенный подбор ключа в браузере (`vigenere-auto.js`)

Нода *Автоподбор Виженера* и кнопка *Подобрать ключ Виженера* используют JavaScript-перенос Python-движка:

* проверяются все варианты алфавита сразу: латиница 26, кириллица 32 (без Ё) и 33;
* **короткий текст (< 60 букв):** перебор коротких ключей и словарная атака (каждое слово словаря как ключ);
* **длинный текст:** частотный анализ по столбцам, затем итерированный локальный поиск (меняем одну букву ключа, оставляем, если оценка выросла, и перезапускаемся с возмущённых ключей);
* при поиске используются триграммы (дёшево); итоговый ранг 60 лучших ключей каждой длины — квадграммы плюс покрытие словарём с бонусом, растущим как покрытие^1,4, и штрафом ln M за каждую букву ключа (M — размер алфавита), так что длинный ключ должен «заработать» свою длину.

### 6.3 Python-движок (`vigenere/`, `backend.py`)

Полный движок — собственный решатель автора. Браузер отправляет `POST /api/vigenere` и опрашивает `/api/vigenere/status`.

* **Алфавиты:** `en-26`, `ru-32`, `ru-33`, `uk-32`, `uk-33`; **варианты шифра:** классический Виженер (P = C − K), Бофор (P = K − C) и вариант Бофора (P = C + K). Один и тот же открытый текст даёт в них разный шифртекст, поэтому движок проверяет все.
* **Сначала анализ:** индекс совпадений для длин ключа до 20 и тест Касиски (расстояния между повторами триграмм) записываются в журнал задачи как подсказки длины ключа.
* **Стратегия** по длине текста: меньше 60 букв — `перебор → словарь → частоты`; иначе — `частоты → словарь → перебор`.
* **Перебор:** все ключи каждой длины делятся на диапазоны и оцениваются на всех ядрах CPU (`multiprocessing`, векторные суммы триграмм в numpy) или на видеокарте (`gpu_scan`: тензоры torch, размер пачки по свободной памяти GPU, при нехватке памяти — автоматический повтор с меньшей пачкой).
* **Словарная атака:** словари до миллионов слов (и их перевёртыши) превращаются в матрицы индексов для каждой длины ключа и оцениваются пачками.
* **Частотная атака и восхождение:** 320 случайных стартов на длину ключа, каждый улучшается побуквенно.
* **Итоговый ранг** (`final_rank`): каждый кандидат получает квадграммную оценку; 600 лидеров ещё и покрытие словарём (вес 6 нат на букву) и штраф ln M за букву ключа.
* **Языковые модели** строятся по корпусам (таблицы n-грамм и множества слов) и кэшируются в файлах `.npz` с подписью содержимого в имени (см. [раздел 2](#2-запуск-и-установка-в-один-клик)).
* Задача, которую 60 с никто не опрашивает, останавливается сама; длина ввода ограничена, и об обрезке пишется в журнал.

## 7. Ссылки, ID и кандидаты в длинном тексте

**Детектор ссылок** (`web/js/links.js`) находит явные адреса, в том числе «обезвреженные» (`hxxp`, `[.]`, `(dot)`) и перевёрнутые, а также «голые» ID, похожие на ID известных сервисов (видео и каналы YouTube, Drive, Catbox, Pastebin, Imgur, приглашения Discord, Telegram…). У каждой находки есть уровень уверенности: 3 — явная ссылка, 2 — характерный шаблон, 1 — только форма.

**Проверки в сети** (только по просьбе пользователя и только через локальный сервер):

* **YouTube:** публичный адрес oEmbed возвращает название и канал, если видео существует. Ответы 400/404 значат «такого видео нет»; 401/403 — «доступ закрыт, видео может существовать», такие ответы не кэшируются.
* **Ссылки:** только адреса `https://` на хостах из списка разрешённых файловых и paste-сервисов (Catbox, Pastebin, Imgur, Drive, Rentry, bit.ly, Яндекс Диск, gist…), порт 443, без логина в адресе. Запрос просит только первый килобайт (`Range: bytes=0-1023`) и **никогда не идёт по редиректу**: вместо этого сообщается, куда он ведёт.

**Кандидаты** (`web/js/candidates.js`) — hex, Base64, двоичные группы, ряды чисел, координаты, ссылки и ID сервисов внутри длинного текста или игрового лога. Каждый кандидат помнит своё место (смещение, строка, столбец), поэтому нода *Найти кандидатов* показывает список, вырезает кандидата по номеру, а авто-поиск может его расшифровать и показать, из какого места лога он взят.

## 8. Картинки: обработка, OCR, шрифт Minecraft, SGA, QR

### 8.1 Обработка (`web/js/image/imgproc.js`)

Все функции для картинок чистые: принимают `{width, height, data}` (RGBA) и возвращают новый объект, поэтому одинаково работают в браузере и в тестах Node. Нода *тона и цвет* последовательно применяет выбор канала, оттенки серого, чёрную и белую точку, **подъём теней**, гамму, яркость, контраст, автоуровни (общие или по каналам), выравнивание гистограммы, инверсию и порог (фиксированный или по Отсу). *Геометрия* — поворот, отражения, масштаб и обрезка по выделенной области. *Битовые плоскости* показывают один бит одного канала; *LSB* извлекает младшие биты выбранных каналов в заданном порядке как байты и текст; *Метаданные* читают PNG-чанки, комментарии JPEG/GIF, EXIF-текст и данные, дописанные после конца изображения.

**Подъём теней** осветляет тёмные тона гораздо сильнее светлых. Так почти невидимая строка цифр в небе примера с тёмным кадром (яркость 13–17 при фоне 9) становится читаемой.

### 8.2 OCR (`web/js/image/ocr.js`)

Распознавание текста — **tesseract.js 5, встроенный в `web/vendor/tesseract`**, с данными для английского, русского и украинского: ничего никуда не отправляется. Нужен локальный сервер: из `file://` браузер не запускает его worker. Перед распознаванием картинка проходит один из вариантов предобработки: *как есть*, *автоконтраст*, *автоконтраст + сглаживание*, *поднять тени* (сильный подъём теней + размытие + инверсия, два уровня), *чёрно-белое* (Отсу), *инверсия*; маленькие картинки увеличиваются. Вариант *авто* перебирает несколько из них, уточняет каждый повторным чтением по строкам и оставляет результат с лучшей уверенностью. Можно выделить область, чтобы читать только часть скриншота; *только цифры* ограничивает алфавит.

### 8.3 Шрифт Minecraft (`web/js/image/pixelfont.js`)

Страницы книг, подсказки предметов и чат используют растровый шрифт, где каждая цифра занимает ячейку в 6 «родных» пикселей (5 на знак + 1 зазор). Читатель находит масштаб (пикселей экрана на пиксель шрифта), режет строку на ячейки по этой сетке, а не по пустым столбцам, и сравнивает каждую ячейку с шаблонами. В курсивных подсказках верхние строки сдвинуты вправо, отчего соседние знаки слипаются, поэтому сдвиг оценивается по всей строке и снимается перед сравнением.

### 8.4 SGA, алфавит стола зачарований (`web/js/image/sga.js`)

1. **Бинаризация:** порог Отсу по яркости; «чернила» — тот класс, что занимает меньшую площадь (работает и для светлого на тёмном, и наоборот).
2. **Строки:** горизонтальная проекция делит картинку на строки текста.
3. **Сетка шрифта:** высота знака — 7 пикселей шрифта; по ней оценивается масштаб, и каждая строка переводится в сетку пикселей шрифта (клетка — «чернила», если чернил в ней достаточно).
4. **Атомы:** столбцы группируются в атомы, разделённые пустыми столбцами. Некоторые буквы SGA состоят из нескольких отдельных частей (`ʖ ꖌ ∷ ∴ !¡`), поэтому атомы — ещё не буквы.
5. **Динамическое программирование по шаблонам:** лучшее разбиение цепочки атомов на буквы выбирается сравнением склеенных групп атомов с 26 шаблонами букв (расстояние Хэмминга; допуск — один пиксель или 12 % «чернил»). Так составные буквы подбираются целиком.
6. **Выход:** латинские буквы клавиш. SGA кодирует латиницу буква в букву, поэтому русский автор, печатающий в английской раскладке, получает текст вида `gjl[jlbn`; выход *кириллица (ЙЦУКЕН)* переводит его в `подходит`.

У каждого знака есть уверенность и рамка на картинке: зелёная — уверенно, жёлтая — шаблон ещё не проверен на настоящих скриншотах, красная — не распознан. На двух настоящих SGA-фото из кейса mslan читаются все знаки (на первом 94, все с уверенностью ≥ 90 %); тест проверяет оба.

### 8.5 QR и штрих-коды (`web/js/image/qr.js`)

QR читает встроенный **jsQR**, остальные штрих-коды — системный `BarcodeDetector`, если браузер его даёт. Настоящие QR на скриншотах часто тёмные, мелкие или бледные, поэтому перебираются варианты предобработки (инверсия, увеличение, контраст).

## 9. Звук и видео

* **WAV** (`media/wav.js`) разбирается точно (PCM 8/16/24/32 бит, float 32/64) с исходной частотой дискретизации; остальные форматы декодирует WebAudio браузера.
* **Спектрограмма** (`media/dsp.js`, `spectro-render.js`): оконное преобразование Фурье; на картинке оси времени и частоты, зум, выделение и воспроизведение. Выход — картинка-артефакт, которую может прочитать OCR: сообщения, нарисованные в спектре, в ARG встречаются часто.
* **Морзе из звука** (`media/morse-audio.js`): поиск тона, огибающая, порог по Отсу, оценка единицы времени по длинам тонов и пауз, точки/тире, паузы между буквами и словами, пометки неуверенных мест.
* **DTMF** (`media/dtmf.js`): алгоритм Гёрцеля измеряет 8 частот DTMF кадр за кадром; тон строки плюс тон столбца дают 0–9, `*`, `#`, A–D. Строку цифр можно подать на операцию *Телефон: нажатия → буквы*.
* **SSTV** (`media/sstv.js`): Robot 36, Martin M1/M2, Scottie S1/S2. FM-демодуляция (смешивание с 1900 Гц, ФНЧ, разность фаз) даёт дорожку мгновенной частоты; заголовок VIS определяет режим, синхроимпульсы 1200 Гц выравнивают строки, значения пикселей читаются вдоль строки в картинку. Проверено на синтетических сигналах; настоящие записи стоит смотреть вручную.
* **Видео по кадрам** (`media/video-node.js`): точный шаг ±1 кадр, номер кадра ↔ время, извлечение кадра, контактный лист и звуковая дорожка — всё как производные артефакты.

## 10. Файлы, архивы и хеши

* **Сигнатуры** (`files/signatures.js`): формат определяется по «магическим» байтам, а не по имени файла. Для PNG, JPEG, GIF, ZIP и других известен конец структуры (после `IEND`, `EOI`, конца центрального каталога), поэтому **данные, дописанные после конца**, находятся и вырезаются. Ещё весь файл сканируется на вложенные файлы известных типов.
* **Строки** (`files/strings.js`): как утилита `strings`, для ASCII, UTF-8 с не-ASCII буквами и UTF-16 LE/BE, со смещениями.
* **Архивы** (`files/archive.js`, `zip.js`, `inflate.js`): список и извлечение ZIP/JAR с inflate на чистом JavaScript, пароли ZipCrypto, вложенные архивы с путями вида `a.zip!inner.jar!X.class`, поиск по всем записям, одиночный gzip; RAR, 7z, tar, xz и другие форматы 7-Zip распаковывает отдельная нода 7-Zip (раздел 16).
* **Java class-файлы** (`files/classfile.js`): разбирается пул констант и выводятся его строки: скрытые сообщения в модах Minecraft часто лежат именно там.
* **Логи** (`files/logview.js`): большой лог с номерами строк, поиском и поиском кандидатов.
* **Хеши** (`files/hash.js`): MD5, SHA-1, SHA-256, SHA-512 и CRC32 на чистом синхронном JavaScript (без `crypto.subtle`, поэтому работают и из `file://`); константы SHA-2 вычисляются из простых чисел. Операции с хешами сравнивают текст или файл с известным хешем.

## 11. Проекты, доски, примеры и досье

* **Проект** (`project.js`): несколько досок (вкладок), общее хранилище улик (артефактов), банк ключей и свои досье. Он автоматически сохраняется в браузере (структура — в localStorage, крупные артефакты — в IndexedDB; тяжёлые улики перезаписываются, только когда меняется их набор) и сохраняется в один файл `.argproj.json` / открывается из него. Старые файлы с одним графом `.json` тоже открываются. Формат версионирован и проверяется при загрузке.
* **Примеры** (`presets*.js`, `presets-kit.js`): 173 доски: задокументированные решения и по примеру на каждую ноду на настоящих данных (`presets-tour.js`; `tests/tour.test.js` падает, если у операции нет примера). У каждого в заметке указаны источник и надёжность, а также либо блок `auto` (исходная строка, ключи, которые раскрыл сам ARG, и ожидаемый ответ, который авто-поиск обязан поставить первым или в тройку), либо причина `manual` (внешний ключ, картинка или звук, действие в игре). Примеры с картинками несут свою картинку отдельным файлом в `web/samples/`, который подгружается только при открытии (`samples.js`): запуск не замедляется, и всё работает из `file://`.
* **Карточка-гид** (`preset-guide.js`): пример открывается с карточкой, где цепочка перечислена в порядке потока данных с результатом каждого шага, ожидаемым ответом, причиной ручного решения, расхождениями источника и кнопкой, запускающей авто-поиск на исходной строке. Карточка обновляется после каждого пересчёта.
* **Досье** (`dossiers*.js`): 17 встроенных досье, по одному на ARG: период, платформа, авторы, статус, кратко, источники, этапы (артефакт → приём → результат → статус), приёмы, открытые вопросы и связанные примеры. Свои досье устроены так же; ссылки на источники проверяются (только `http(s)`).

## 12. Клавиатуры, рисование, отладка

* **Экранные клавиатуры** (`keyboards.js`, `kb-*.js`, `sga-keyboard.js`): SGA, шрифт Брайля (с построителем клетки по точкам), Морзе, руны (младший футарк), греческий, пигпен, спецсимволы и двойники (похожие буквы латиницы и кириллицы). Знаки вставляются в поле с фокусом или в черновик панели; строка *Читается как* сразу показывает расшифровку.
* **Рисование** (`annotations*.js`): карандаш, стрелки, рамки, эллипсы, подписи и картинки на доске; хранятся в мировых координатах (двигаются и масштабируются вместе с графом), входят в отмену и в файл проекта. Стрелка-аннотация никогда не соединяет порты: это заметка, а не данные.
* **Вкладка «Отладка»** (`debug.js`): проверяет, что загрузились все модули интерфейса, языковые данные и операции, прогоняет несколько известных расшифровок целиком и спрашивает у сервера Python, numpy, PyTorch, CUDA, состояние движка, время загрузки моделей и хеши файлов данных. *Скопировать отчёт* кладёт всё это в буфер обмена для сообщения об ошибке. Сервер отвечает по-русски; английский интерфейс переводит его сообщения (`server-text.js`).

## 13. Безопасность и приватность

* Сервер слушает **только 127.0.0.1**. Запросы к API должны приходить с заголовком `Host` равным `127.0.0.1` или `localhost` (защита от DNS rebinding), а запросы `POST` — с заголовком `X-ARG-Decoder: 1`, который чужая веб-страница не может прислать без предварительного CORS-запроса.
* **Ни телеметрии, ни аккаунтов.** Программа выходит в сеть только:
  * при первой установке: python.org за Python на Windows, PyPI за numpy/torch и RapidOCR, modelscope.cn за моделями OCR, релиз GitHub за данными;
  * для **проверки обновлений**: при запуске, не чаще раза в 6 часов, локальный сервер читает список релизов с `api.github.com` (данные о пользователе и проекте не отправляются; проверку можно выключить в «Отладке», `--offline` отключает её), а файлы релиза скачивает с `github.com` только после нажатия «Обновить»;
  * когда пользователь сам просит проверить YouTube или ссылку. Проверка ссылок ограничена списком разрешённых хостов и не ходит по редиректам.
* **Обновлениям верят только по подписи.** Список файлов релиза (`build.json`) подписан Ed25519 ключом автора, открытая половина которого встроена в `updater.py`. Каждый файл архива сверяется с этим списком до установки. Заменяемые файлы копируются в резервную копию вместе с хешами. Откат сначала проверяет копию и ничего не трогает, если она неполная, а после восстановления сверяет результат; при сбое записывается `rollback-failed` со списком файлов, а не сообщение об успехе.
* Скачанный архив данных и каждый файл в нём сверяются с SHA-256 из `data.manifest.json`; распаковываются только плоские имена файлов внутри `data/`.
* Проекты и файлы остаются в хранилище браузера на этом компьютере или в файле проекта, который пользователь сохранил сам.

## 14. Тесты

* `node --test` запускает набор JavaScript-тестов (больше 400): каждая операция, граф, решатель, каждый пример (должен вычисляться без ошибок и давать задокументированный ответ на обоих языках), авто-поиск на каждом примере с `auto`, обработка картинок, SGA и шрифт Minecraft на настоящих скриншотах, звуковые декодеры на синтетических сигналах, файловые инструменты, формат проекта, досье, клавиатуры, переводы.
* `python -m unittest discover -s tests -p "test_*.py"` проверяет сервер и установщик данных (нет файлов, битый архив, опасные пути).
* `node tools/check_i18n.js` падает, если какая-то кириллическая строка интерфейса не обёрнута в `T('ru', 'en')`; `node tools/gen_functions_doc.js --check` падает, если справочник функций устарел.
* GitHub Actions запускает всё это на Windows, macOS и Linux.

## 15. Доказательность, движки и медиа после аудита 2026-10-23

**Статусы вместо одного флага «уверенно»** (`solver-evidence.js`). У каждого результата один из статусов: *уверенно* (детерминированное снятие слоя формата, в котором вход действительно записан, до читаемого текста, ссылки, координат, пути к файлу или числа; либо подбор параметров, где буквы, покрытые словами, явно перевешивают число перебранных вариантов), *вероятно* (читается, но свидетельств мало: короткий текст, угаданные параметры), *формат распознан* (хеш, контейнер OpenSSL `Salted__`, непрозрачный идентификатор — открытого текста нет), *часть входа* (расшифрован кусок) и *гипотеза*. Поиск заканчивается итогом: решено, есть варианты, распознан формат или **ответ не определён**. Проверки формата строгие: у Base64 правильный алфавит и длина, у Base32 один регистр, у hex чётное число цифр. Печатаемый ASCII считается свидетельством только после байтового декодера (Base64, hex, двоичный…), но не после «числа → буквы». Шаг, не поднявший читаемость, уверенности не даёт. Штраф за множественные сравнения тает с числом букв, покрытых словами: верная длинная расшифровка не тонет, а пятибуквенное слово через три угаданных шага остаётся гипотезой.

**Распознавание входа.** До поиска арифметическое выражение считается точно (`2*3*76543` → 459258), hex стандартной длины дайджеста с буквами a–f помечается как хеш, одиночный токен из букв и цифр (`1v7531`, `794e2cea991`) остаётся как есть.

**Python-движок внутри «Авто»** (`solver-engines.js`). Если вход похож на буквенный шифртекст и работает локальный сервер, полный Python-подбор Виженера стартует параллельно с браузерным поиском, в пределах бюджета времени (по умолчанию 20 с) и с отменой. Его ключи заново применяются операцией Виженера графа (точные пробелы и регистр) и оцениваются как любые кандидаты, с поправкой на длину ключа (около 3 бит на букву плюс 10). Если букв текста меньше трёх на букву ключа, кандидат помечен «ключ недоопределён». У каждого кандидата есть происхождение (движок, ключ, алфавит, время) и ещё один уровень поиска цепочки. Без сервера панель так и пишет. В банк ключей проекта найденные ключи не попадают.

**Составные сообщения и перестановки** (`solver-crackers.js`). Если строкам входа нужны разные схемы, каждая строка решается отдельно, а части собираются с исходными переводами строк операцией графа *Части по строкам* (`segment_map`); её JSON-план воспроизводит результат. Если частоты букв как у языка, а квадграммы нет, порядок столбцов перестановки подбирается восхождением с зерном от текста (один вход — один и тот же ход поиска), сравниваются циклические сдвиги ключа, ответ воспроизводит обычная нода *Перестановка столбцов по ключу*. Если есть уверенное решение всего входа, куски показываются ниже него.

**Байты, файлы и картинки.** XOR в авто-поиске выполняется с теми же значениями по умолчанию, что в графе; *XOR с пропуском знаков* использует тот же разбор ключа и имеет правило для байтов (не трогать пробелы, точки и запятые). Новые ноды: *Байты → файл*, *Файл → байты*, *Склейка файлов (байты)* (с границами частей и заявленной длиной PDF), *Биты → картинка* (дальше QR и OCR), *Изображение: две картинки → одна* (разность, XOR, сумма, умножение, «экран», среднее, прозрачность, сдвиг) и *Байты → звук (raw PCM)*. Кадры, листы и звук, извлечённые из видео, сохраняются с проектом. У книжного шифра есть точная разметка (символы как есть, слова по одному пробелу, первый номер 0 или 1).

**SSTV на настоящих записях.** Дорожка частоты сглаживается медианой (1,5 мс) перед поиском синхроимпульсов. Без VIS-заголовка режим выбирается по периоду строк (интервал в одну строку весит больше, поэтому Robot 36 не путается с Martin M1). Длина строки измеряется по записи, картинка начинается с первой устойчивой серии синхроимпульсов. В результате указано, как найден режим, и качество (доля строк с настоящим синхроимпульсом). Построенная картинка — ещё не решение загадки.

**Восстановление QR.** Если обычные варианты не прочитались, картинка делится на сетку N×N, три ориентира и линии синхронизации дорисовываются по стандарту, и jsQR запускается снова. Такой результат помечен «восстановлен: дорисованы ориентиры». Модули данных не меняются.

**RAR.** Нода ZIP по-прежнему только сообщает о заголовках RAR4 (зашифрованы или нет); распаковка перешла в ноду RAR/7z из раздела 16.

## 16. После ревью 2026-10-24 (1.2.0)

**Сначала слои формата.** До лучевого поиска слои строго проверенного формата (процентный, hex, двоичный, Base64, Base32, Ascii85) снимаются подряд, до шести, а чтение UTF-8 считается частью шага декодера. Лучевой поиск может повторить декодер до четырёх раз подряд, а состояние, уже встречавшееся выше в той же цепочке, отбрасывается (защита от циклов). Поэтому `Base64(Base64(Base64(текст)))` не тратит глубину поиска.

**Снято — не значит подтверждено.** Детерминированное декодирование *уверенно*, только если вывод подтверждает себя: читаемый текст от 6 букв с покрытием словарём от 60 %, ссылка на весь вывод, координаты, путь или посчитанное выражение. Иначе это *формат снят, ответ не подтверждён* (`decoded`): `UE9UUw==` → `POTS` — верное декодирование, но `STOP` остаётся в списке. Перевёрнутая ссылка (`gnp.…//:sptth`) — подсказка для реверса, а не ссылка; схема, искажённая шифром (`frrnq://`), — следующий слой. Ссылка внутри длинного текста подтверждает только себя: текст вокруг должен читаться, иначе «как есть» — *часть входа*, а преобразования и Python-движок к нему всё равно применяются. Язык оценивается по тексту без ссылки, поэтому латиница адреса не топит украинскую фразу.

**Перестановки и порядок слов.** Реверс по словам стоит дороже реверса всей строки; заглавная в начале и точка в конце дают небольшой бонус. Если два порядка одних и тех же букв читаются одинаково (в пределах 3 очков), лидер помечается *вероятно* с пометкой «неоднозначно».

**Очередь движка.** Python-подбор Виженера — очередь на один поиск: вход, затем до двух промежуточных буквенных слоёв, полученных точным декодированием (Base64 → `JSH ALWE PROIR…`). Одинаковые тексты не повторяются, бюджет времени и отмена общие, найденный ключ применяется к этому слою, поэтому цепочка `Base64 → байты → Виженер(ключ)` воспроизводится в графе.

**Поиск с ограничениями формата.** Перестановка столбцов оценивается моделью алфавита текста (EN, RU или UK). Перемешанная ссылка (есть все символы `https://`, нет пробелов) ищется по порядкам столбцов, при которых расшифровка начинается с `https://` или `http://`, с неполной последней строкой, и остаются только целые ссылки. Виженер над ссылкой берёт буквы ключа из известного начала (`https`, `www` или хост известного сервиса с той же длиной частей — точки сохраняются); каждая буква ключа проверяется хотя бы раз, и сходиться должны минимум две лишние проверки.

**OCR.** Каждая строка уточняется отдельно, и исходная строка остаётся, если уточнение потеряло символы; строки любой длины считаются. Для голосования нужно согласие разных семейств предобработки (dark/dark70 — одно семейство), и группа с нулевой уверенностью не заменяет содержательный результат. В режиме цифр короткая строка рядом с длинной убирается, только если ни одно другое семейство не видело тот же текст в том же месте; убранные строки возвращаются с предупреждением. Возвращаются сырой текст, рамки, альтернативы и все кандидаты. Ни один символ не подменяется. Порядок «авто»: шрифт Minecraft → RapidOCR как есть → RapidOCR с автоконтрастом → tesseract; ветка принимается, только если ответ не пуст, а для цифр — только из цифр и пробелов (отклонённые ответы сохраняются, не вычищаются).

**Сервер RapidOCR.** `setup_ocr.py` ставит RapidOCR 3.10.0 и ONNX Runtime 1.20.1 в `runtime/ocr-python` (папка добавляется в конец `sys.path`, поэтому numpy основного Python остаётся главным) и три модели из `config/ocr-models.json` в `data/ocr` со сверкой SHA-256. `POST /api/ocr` принимает PNG и `en` или `cyrillic`, собирает блоки в строки по перекрытию по вертикали и возвращает сырой текст, рамки и оценки; `GET /api/ocr/status` объясняет, чего не хватает.

**Архивы.** Нода *Архив RAR/7z (7-Zip)* запускает 7-Zip 24.09, собранный в WebAssembly и загружаемый по требованию. Каждая операция — новая файловая система в памяти, пароль всегда передаётся явно (`-p`), чтобы 7-Zip ничего не спрашивал, вывод ограничен 256 МБ и 5000 файлами. Неверный пароль, повреждённый архив и неподдерживаемый формат называются отдельно.

**Машины и кодировки.** Энигма I/M3/M4: роторы I–VIII, Beta/Gamma, рефлекторы A/B/C и тонкие B/C, кольца, стартовые позиции, коммутатор и двойной шаг среднего ротора; сверена с опубликованными сообщениями 1941 (M3) и 1942 (M4). Сырой RC4 отделён от контейнера OpenSSL. *Группы битов → строки сетки* раскладывает дамп, напечатанный группами и колонками текста; с 12,12,13 битами, 3 группами в строке и 3 колонками дамп Sombra становится QR 37×37, который читается «¿Estuvo eso facilito? …».

**Испанский.** Для латиницы в оценке есть испанская модель квадграмм и слов (Tatoeba). Ей нужно более сильное свидетельство, чем английской (покрытие 60 % и два слова или ñ/á/¿), чтобы случайные строки не становились «испанскими».

**Сжатые слои.** *Распаковать zlib / gzip / deflate* использует тот же распаковщик на чистом JS, что и чтение ZIP. «Авто» выбирает gzip (`1F 8B 08`) или zlib (метод CMF 8, окно ≤ 32 КБ, CMF·256+FLG делится на 31) по заголовку; сырой deflate принимается, только если поток заканчивается не дальше одного байта от конца входа. Проверяются Adler-32 или CRC-32 с длиной; несовпадение — ошибка в строгом режиме и предупреждение в обычном. В авто-поиске поток с сошедшейся контрольной суммой считается слоем формата и снимается сразу; результат может вырасти до 1 МБ (обычный предел в 5 длин входа после распаковки не действует). XOR над сжатыми данными получает дополнительные ключи из заголовка как известного открытого текста: один байт — из любого допустимого CMF/FLG, два — из `78 01/5E/9C/DA`, от одного до трёх — из `1F 8B 08`; контрольная сумма распаковки подтверждает или отвергает каждый ключ. У сырого deflate нет ни заголовка, ни суммы, поэтому после XOR он остаётся *вероятным*.
